0.2第零幕 · 它到底是什么·AGENT VS THE REST

它和另外三样东西差在哪

大模型、工作流、RPA、Agent，四个词天天混着用。其实只差一个问题：下一步谁说了算。这一页用一张表和一把伞把分界划清。

6 分钟 零基础 含对照表
这一页在能力栈上的位置
对应环节定义层 · 与相邻概念的分界
不学卡在哪把所有「接了 API 的模型」都叫 Agent，于是估错了它的能力与风险。
它解决什么给出可操作的判断标准，能一眼区分工作流与 Agent。

1一张表分清四样东西

这四个词天天被混着用，其实差在「谁决定下一步」这一个问题上：

你给什么谁决定下一步像什么
大模型 / Copilot指令（prompt）你。它只负责把这一步答好副驾驶：你握方向盘，它帮你看路
工作流 / 编排流程图图。每一步走哪条边是事先画死的流水线：工件自己往前走
RPA录制好的操作录制时的那次操作复读机：遇到没录过的界面就卡住
Agent目标它自己。边走边判断，走错了回头主驾驶：目的地说了，路线它定

RPA 最容易被误当成 Agent。区别不在「自动化」——两者都自动——而在面对没预设过的信息时还能不能判断。RPA 的流程里没有「如果弹窗长得不一样怎么办」这一支，Agent 有。

2一个日常例子：明天去成都要不要带伞

只有聊天输出文字

它只能凭训练时记住的气候常识猜一句：「成都雨水多，建议带伞。」

听着有道理，但它其实不知道明天的天气。它没查，也没法查。

有 Agent输出动作 → 拿回结果 → 再输出结论

它先去查天气预报，看到「明天小雨、12 度」，再回来告诉你——而且说得出自己是查的、查的是哪个源。

差别不在它更聪明。差别在有人给了它一双手。

这个差别看着小，但它决定了后面所有工程问题的来源：有了手，就要处理手会抓空、会抓错、会把东西打翻。

3会聊天，不等于会干活

先立一个判断标准：能陪你聊天的，不一定叫 Agent；能自己想办法把事办完的，才是。

按这个标准回头看市面上的产品，会发现一个现象：很多自称 Agent 的东西，其实是一条写死的工作流，只是中间插了一次模型调用。它不是不能干活，是不会在计划外的事上做决定。

判断方法：给它一个你没预设过的意外（接口报错、数据缺一列、用户改需求），看它是绕过去继续、还是整条停住。停住的，就是工作流。

本页要点

  1. 四样东西的分界只有一条：谁决定下一步。
  2. RPA 与 Agent 的区别不在自动化，而在遇到没预设的信息时还能不能判断。
  3. 很多自称 Agent 的产品其实是插了模型调用的工作流，测它一个意外就能看出来。
