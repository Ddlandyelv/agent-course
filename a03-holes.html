1大模型自己缺的六样

为什么非要给它加外面那层？因为单靠模型，有六件事它做不到：

缺什么具体表现Agent 怎么补
会编一本正经地说不存在的事实要求它先查再答，答案带出处
不知道现在训练数据有截止日期接搜索 API，现查现用
算不准多位数乘法容易错把计算丢给代码解释器
没有手只能说「我无法购买咖啡」接下单、支付这类真实接口
记不住换个会话就忘了你是谁外部记忆库，按需检索
做不长任务一长就跑到一半停住规划 + 断点续跑

所以有个说法很准：如果大模型是大脑，Agent 就是小脑加手脚。大脑负责想，小脑负责把想法变成协调的动作，手脚负责真的碰到世界。

2六缺里，哪一个最要命

六个不是并列的。按「不补就会出事」排序：

  1. 没有手——不补，它永远只能输出文字，做不了任何事。这是 Agent 存在的理由。
  2. 会编——不补，它会用最自信的语气给你错的结果，而且你很难发现。
  3. 记不住——不补，它会在同一个坑里反复摔，长任务永远做不完。
  4. 做不长——不补，任务一到十步以上就断在半路。
  5. 不知道现在——不补，所有涉及时效的问题都只能靠猜。
  6. 算不准——不补，数字类任务不可信，但这个最容易用工具绕过。

「算不准」排在最后，不是因为它不严重，而是因为它最好修：给一个计算器就解决了。难修的是「会编」和「记不住」，它们需要外部信号和检索策略，不是加个接口能搞定。

3这六缺决定了后面每一页在讲什么

缺的东西对应本课哪几页
会编 / 不知道现在05 工具调用、06 ReAct（先查再答）
没有手05 工具调用、03 harness（把话变成动作）
记不住08 记忆（三层记忆与检索策略）
做不长09 搜索与回溯、07 反思（错了重来）
算不准05 工具调用（把计算外包出去）

换句话说，Agent 的每一个零件，都是为了补上这六缺里的某一缺。记住这张对照表，后面读到任何新框架，都能立刻问一句：它补的是哪一缺？

本页要点

  1. 大模型自己缺六样：会编、不知道现在、算不准、没有手、记不住、做不长。
  2. 最要命的是「没有手」和「会编」，最好修的是「算不准」。
  3. Agent 的每个零件都在补其中一缺——新框架也可以用这张表来定位。

★自测

Q1六个缺口里，为什么「算不准」反而最好解决？
难修的是需要外部信号的（会编、记不住）。算不准只要给个工具就行，属于工程上最容易补的一类。
Q2「没有手」具体指什么？
这是 Agent 存在的根本理由。工具调用就是把「说」变成「做」的那一步。
