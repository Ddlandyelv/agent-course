06第二部分 · 从会说话到会动手·REACT

让思考接上行动：ReAct

想一步、做一步、看一眼，再接着想。这一页讲清它为什么成了所有 Agent 框架的默认骨架，以及它会在哪四种地方跑偏。

10 分钟 · 重点 含失败模式 全课骨架
这一页在能力栈上的位置
对应环节能力层 · 行动 + 推理的耦合
不学卡在哪只会让模型「一次想完再输出」，于是遇到需要查证的任务就一路编到底。
它解决什么给出可循环、可纠错的最小智能行为。

1缺什么：光想会脱离事实，光做又没计划

纯 CoT 只能靠模型脑子里记的东西——记错了就一路错到底，没人纠。纯行动又没有规划，走一步算一步。

2022 年 10 月，Yao 等人把两者交替起来：先写 Thought，再调 Action（比如查维基），拿到 Observation 再接着想。

Thought想下一步
→
Action调工具
→
Observation看结果
→
Thought修正后继续

关键在第三步：观察结果会当场推翻它上一句的错判。这是 CoT 做不到的——它没有外部输入。

2为什么它是所有 Agent 框架的默认骨架

因为它把一个很难的问题拆成了两个简单的问题：

原本的难题ReAct 的拆法
一次想清楚整条路只想下一步，走完再看
判断自己想的对不对让环境告诉它对不对
计划赶不上变化每轮都重排，计划是临时的

LangChain 的 create_agent、LangGraph 的 create_react_agent，底下跑的都是这个循环。可以说整个 Agent 工程就是从这篇开始的。

关键数字arXiv:2210.03629 · ICLR 2023 Oral

ALFWorld 绝对成功率 +34%、WebShop +10%（对比只用行动的方法）；HotPotQA 上的幻觉比纯 CoT 明显少。

3它的失败模式

ReAct 好用在简单，坏也坏在简单。四种常见跑偏：

失败模式表现怎么防
绕圈反复查同一个东西，得到同样结果还在查检测重复动作，命中就强制换策略或停
越走越远为了查 A 去查 B，为了 B 去查 C，忘了原任务每 3 轮把原始目标复述一遍进上下文
观察污染工具返回的无关内容太多，把关键信息挤掉回填前做摘要或截断
假装看过没调工具，直接说自己查了记录真实的调用日志，和它的自述比对

代价：轮数不可控，长任务容易绕圈把自己绕进去；每一轮都是一次完整调用，成本线性上涨。

4今天的对应

几乎所有 Agent 产品的主循环都是 ReAct 的变体。差别只在：给它什么工具、允许它走多少轮、失败时怎么收场。

判断一个 Agent 产品好不好，先看它的轮数上限和重复动作检测——这两样有没有，基本能看出是「演示」还是「能用」。

本页要点

  1. ReAct = Thought → Action → Observation 交替，用真实结果修正下一步。
  2. 价值在「接地」：答案来自刚查到的内容，不是训练时的记忆。
  3. ALFWorld +34%、WebShop +10%，是所有 Agent 框架的默认骨架。
  4. 四种跑偏：绕圈、越走越远、观察污染、假装看过。

★自测

Q1ReAct 相比 CoT，最本质的增量是什么？
CoT 只在脑子里想，错了没人纠。ReAct 每走一步都能拿到环境的反馈，这是「接地」的来源。
Q2它反复查同一个东西、结果一样还在查，属于哪种失败？
绕圈的检测方法很机械：记录最近的（工具, 参数）组合，重复出现就强制换策略。
