1任务复杂到单个撑不住，就有几种固定形态

拆成多个角色之后，「他们怎么说话」是要设计的。以微软开源的 AutoGen 为例，它把协作方式归纳成几种固定形态：

2双人对话：最便宜的一种协作

两个角色，一正一反。它之所以有效，是因为「审」和「做」用了两套不同的上下文——审核的人看不到执行者的思考过程，只能看结果。这恰好抵消了自查的盲区。

实现上最简单：两个 system prompt，轮流把对方的话当输入。不需要调度器，不需要共享状态。

如果你的需求是「产出物要有人挑错」，先试双人对话。它比群聊便宜一个数量级，效果常常更好。

3群聊：谁说话是个问题

多个角色在一个对话里，必须有个人决定「下一个谁发言」。常见三种调度：

调度方式怎么决定风险
轮流按固定顺序转一圈某个角色没事也要发言，浪费且跑题
模型选让一个调度角色看当前状态，指定下一位调度者自己也会误判
规则 + 模型先按条件过滤候选，再让模型选实现复杂，但最稳

群聊最大的坑不是调度，是上下文膨胀：每个角色都要读全部历史，五轮之后每个角色的输入都变得又长又吵。

4层级：像公司一样分工

Manager 拆任务、Worker 执行、结果汇总。它适合可并行拆分的任务，比如「同时调研五个方向」。

好处是每个 Worker 的上下文都很干净——它只知道自己那一小块。坏处是 Manager 成了瓶颈：拆得好不好，直接决定整体质量。

MetaGPT 是这条路的极致：把软件公司的分工整个搬进来，产品、架构、开发各扮演一个 Agent，能从一句话生成 PRD 和接口设计。体系重、学起来陡，但确实演示了「组织即架构」这件事。

5别家怎么表达同一件事

框架它的隐喻本质对应
AutoGen几个 Agent 开会群聊 / 层级
CrewAI组一个团队，有角色有分工层级 + 角色提示
MetaGPT一家软件公司带固定 SOP 的层级
OpenAI Agents SDK交接（handoff）双人对话的链式串联

隐喻不同，落到实现上都是「谁在什么时候、拿着什么上下文、说什么话」。把这句记住，换框架时不用重学。

本页要点

  1. 三种形态：双人对话、群聊、层级，AutoGen 的归纳。
  2. 双人对话最便宜，「审」与「做」用两套上下文，天然抵消自查盲区。
  3. 群聊的坑是上下文膨胀，层级的瓶颈是 Manager 的拆解质量。
  4. 换框架时只需问：谁、在什么时候、拿着什么上下文、说什么话。

★自测

Q1双人对话为什么比让同一个 Agent 自查更有效？
关键在上下文隔离。自查时它知道自己的意图，于是会自动「理解」自己的错误。
Q2群聊这种形态最主要的工程风险是什么？
五轮之后，每个角色的输入都又长又吵。要么压缩历史，要么改成层级。
