1缺什么：每次都是初次见面

模型本身没有记忆。所谓「它记得我说过的话」，是你每次把记录重新贴给它看。贴不进去（超出上下文）或没贴（换了个会话），它就真的忘了。

所以记忆模块要解决的从来不是「存」，而是「此刻该想起哪一条」。这是它最常被低估的地方。

2人的三层，Agent 的三层

这个映射不是修辞，工程上真的这么分：

人的记忆Agent 里对应什么限制
感觉记忆原始输入的嵌入表示：文本、图像、音频都先变成向量只在当下有效，不保留
短期记忆上下文窗口里的对话历史有硬上限，塞满就得压缩或丢弃
长期记忆外部向量数据库，按需检索存得下，但「取哪条」是难题

长期记忆为什么用向量库？因为它要解决「海量知识的存、检、配」。把数据转成向量之后，用最大内积搜索（MIPS）能在毫秒级找出语义相近的条目——注意是模糊匹配，没有标准答案，这正是它能支撑开放场景的原因。

成本上也有账：向量库的存储成本比把知识塞进神经网络低 2 到 4 个数量级。所以在上下文窗口还很贵的今天，外挂记忆库比自己训模型划算得多。

3Generative Agents：记忆流四步

2023 年 4 月，Stanford 的 Park 等人在一个叫 Smallville 的小镇里放了 25 个角色，每个都有「记忆流」：

观察经历记成自然语言
→
检索三项打分取前几条
→
反思零散记忆总结成结论
→
计划据此排一天的行程

检索按三个维度打分：新近度（刚发生的更容易想起）、重要性（打分来自模型自己判断）、相关性（和当前情境的语义相似度）。

最有名的结果是涌现出来的：只告诉一个角色「想办情人节派对」，两天后邀请自己扩散开，人真的到场了——没有一行代码编排这场派对。

4MemGPT：把上下文当内存管

上下文窗口再大也有限。聊得久了必然塞不下，而无脑截断会把它刚记住的关键信息扔掉。

MemGPT 借操作系统的内存管理：上下文 = 内存（快但小），外部存储 = 硬盘（慢但大）。模型自己调函数在两者之间搬数据——写回、换入、检索。「该忘什么」由它自己判断，不是按时间粗暴删。

OS 里的概念MemGPT 里对应作用
内存上下文窗口当前推理能直接看到的内容
硬盘外部存储 / 向量库放得下但需要主动换入
换页模型自己调的记忆读写函数决定什么进、什么出
中断上下文快满时触发整理避免直接报错

局限：多了一层「管理记忆」的调用，成本和延迟都上去；搬错了会直接把关键信息弄丢，而且很难发现。

5做记忆最常见的三个错

错法后果改法
把全部对话原样存下来检索时噪声太多，取回来的都是无关闲聊存「结论与事实」，不存过程
只按时间倒序取三个月前那条关键约束永远想不起来新近度 + 相关性 + 重要性，三项加权
写完就存，从不整理同一条事实存了二十遍，互相矛盾定期合并、去重、更新而不是追加

一条实用经验：存「我学到了什么」，不存「我说了什么」。Reflexion 的复盘之所以好用，就是因为它存的是结论。

本页要点

  1. 记忆的难点不在存，在「此刻该想起哪一条」。
  2. 三层：嵌入表示（当下）、上下文（短期）、向量库（长期）。
  3. Generative Agents 的四步：观察 → 检索（新近度/重要性/相关性）→ 反思 → 计划。
  4. MemGPT 把上下文当内存、外部存储当硬盘，由模型自己决定换入换出。

★自测

Q1长期记忆为什么常用向量库？
记忆检索是模糊匹配，不是精确查询。用户问「上次那个关于预算的结论」，你不可能用 SQL 精确匹配。
Q2Generative Agents 的检索按哪三个维度打分？
三项加权是这套设计的核心。只用新近度会丢长远约束，只用相关性会反复想起同一件事。
