03第一部分 · 它由什么拼成·THE HARNESS

harness：套在模型外面的那层

模型的全部能力，都要靠这层程序翻译成动作。它做六件事，其中两件最容易把项目搞垮。这一页是全课最该精读的一页。

12 分钟 · 重点 含最小代码 读完能自己写循环
这一页在能力栈上的位置
对应环节结构层 · 运行时
不学卡在哪只会调 API，不会处理工具调用、错误和停止条件，于是做出来的东西「一遇意外就全乱」。
它解决什么把运行时拆成六个可分别检查的步骤，并给出最小可用实现。

1马具：套在马上、让它能拉车的那套带子

harness 直译是「马具」——套在马上、让它能拉车的那些带子。中文常译成「脚手架」或「运行框架」，意思都一样：它是套在模型外面、把模型的力量用出来的那层程序。

大白话一句：模型只会「说话」。把它说的话变成真动作的，是外面这层。

这个词现在也指「评测用的统一外壳」——同一个模型换不同 harness，成绩能差出一大截。原因就在这一页讲的六个步骤里。

2一次工具调用，中间有六步

以「明天去成都要不要带伞」为例，看这层程序到底做了什么：

步谁做在干什么最容易出的错
① 拼装你的程序把「你是谁 + 聊过什么 + 有哪些工具 + 这次的问题」拼成一段话发过去上下文塞爆，或删掉了关键信息
② 解析你的程序从模型的回话里认出「它想调哪个工具、参数是什么」模型编了一个你没提供的工具
③ 执行你的程序真的去调接口，拿到「明天下雨 12℃」超时、报错、返回乱码
④ 回填你的程序把结果补进对话记录，再发一次结果太长被截断，或报错被吞掉
⑤ 生成模型这才说出：明天有小雨，建议带伞它无视刚查到的结果，继续说旧结论
⑥ 判断停止你的程序看它这次还要不要用工具；不要就结束没有上限，来回调几十次刷爆账单

顺手还要做：超过 10 轮强制停、接口超时重试、把这次花了多少钱记下来。

3四个最容易做错的地方

① 拼装：删哪一段没有标准答案。模型能读的字数有限，聊久了塞不下，你得决定删掉哪一段。删早了它忘事，删晚了直接报错。这件事全靠按场景调，没有通用解。

② 解析：模型回的不是代码，是一句话。它可能说「我想用查天气这个工具」，也可能直接编一个 JSON。你的程序得从中认出这是一次工具调用，还要防它瞎编——比如它说要用一个你根本没提供的工具。

③ 执行：这是唯一真正碰到真实世界的一步。接口会超时、会报错、会返回乱码。模型不知道这些，它只在那儿等。所有失败都得你的程序接住，并且如实告诉它——别把错误吞掉，那会让它以为查成功了。

⑥ 判断停止：最容易被忽略、也最容易出事。没有上限，它可能来回调几十次工具，一夜之间把账单刷爆。

同一个模型，harness 写好写坏，效果天差地别。这不是模型不行，是外面这层没做好。

4最小可用的循环长什么样

抛开框架，一个能跑的最小版本就这么点东西：

messages = [{"role":"system","content": ROLE},
            {"role":"user","content": question}]

for step in range(MAX_STEPS):        # ⑥ 先有上限
    resp = model(messages, tools=TOOLS)
    messages.append(resp)            # ① 记录这一轮
    calls = parse_calls(resp)        # ② 解析它要调什么
    if not calls:                    # ⑤ 不调工具 = 可以收工
        break
    for c in calls:
        try:
            result = run(c)          # ③ 真的执行
        except Exception as e:
            result = {"error": str(e)}   # 失败也要回填，别吞
        messages.append(tool_msg(c, result))   # ④ 回填
return messages[-1]

这二十来行就是全部原理。LangChain、LangGraph 做的事情，是把这二十行里的每一步做得更稳、可观测、能续跑——不是换了一套原理。

本页要点

  1. harness 是套在模型外面那层程序：模型只说，它负责把话变成动作。
  2. 一次工具调用六步：拼装 → 解析 → 执行 → 回填 → 生成 → 判断停止。
  3. 最容易出事的两步是「执行」（失败没人接）和「停止」（没有上限）。
  4. 二十行代码就是全部原理，框架只是把每一步做稳。

★自测

Q1模型输出了一个你没提供的工具名，问题出在哪一步？
模型会编工具。解析这一步必须做白名单校验，不在列表里的直接拒绝并告诉它「没这个工具」。
Q2为什么工具执行失败也要把错误回填给模型？
回填的内容直接决定它下一轮是变聪明还是变傻。吞掉错误是常见的隐性 bug。
Q3没有轮数上限会怎样？
这是最容易被忽略、也最容易出事的一步。LangGraph 的 recursion_limit 默认 25 就是为了这个。
